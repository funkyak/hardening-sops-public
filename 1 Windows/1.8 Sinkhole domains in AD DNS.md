Up: [[0 Start here]] · Safety: [[0.1 Before any change]]

Makes a bad domain (and all its subdomains) resolve to `0.0.0.0` for every client that uses AD DNS.

## Check

```powershell
Resolve-DnsName bad.example.com -Server <DC>
Get-DnsServerZone | Where-Object ZoneName -eq 'bad.example.com'
```

## Do

Option A works on any Windows DNS server. Run on one DC; it replicates to the forest.

```powershell
$domain = 'bad.example.com'
Add-DnsServerPrimaryZone -Name $domain -ReplicationScope Forest
Add-DnsServerResourceRecordA -ZoneName $domain -Name '@' -IPv4Address 0.0.0.0 -TimeToLive 01:00:00
Add-DnsServerResourceRecordA -ZoneName $domain -Name '*' -IPv4Address 0.0.0.0 -TimeToLive 01:00:00
```

Option B, Server 2016 and later: a query policy that drops the query instead, with no zone to manage.

```powershell
Add-DnsServerQueryResolutionPolicy -Name 'block-bad-example' -Action IGNORE -FQDN 'EQ,bad.example.com,*.bad.example.com'
```

Option B is per server: run it on every DC that answers DNS.

Clients cache answers. On a client: `ipconfig /flushdns`. On the DC: `Clear-DnsServerCache -Force`.

> [!note] Clients can bypass this
> Anything using its own resolver (8.8.8.8, DNS over HTTPS) skips AD DNS. Block outbound TCP/UDP 53 at the firewall for everything except the DCs, and block the IPs too ([[3.1 pfSense|3.1]]).

## Verify

```powershell
Resolve-DnsName bad.example.com -Server <DC>       # 0.0.0.0 (A) or no answer (B)
Resolve-DnsName www.bad.example.com -Server <DC>
```

## Roll back

```powershell
Remove-DnsServerZone -Name bad.example.com -Force
Remove-DnsServerQueryResolutionPolicy -Name 'block-bad-example' -Force
```
