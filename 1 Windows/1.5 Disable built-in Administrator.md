The built-in Administrator (RID 500) is the first account attackers try. Disable it in the domain and on member machines once `breakglass` is proven to work.

## Check

1. `breakglass` exists, is enabled and is a Domain Admin, and you have logged in with it:
   ```powershell
   Get-ADUser breakglass -Properties Enabled, MemberOf | Select-Object Enabled, MemberOf
   ```
2. Find the built-in account by its SID, since it may have been renamed:
   ```powershell
   $admin = Get-ADUser -Filter * | Where-Object { $_.SID -like '*-500' }
   $admin | Select-Object SamAccountName, Enabled
   ```
3. Check nothing runs as it (services, scheduled tasks):
   ```powershell
   Get-CimInstance Win32_Service | Where-Object StartName -match "\\$($admin.SamAccountName)$" | Select-Object Name, StartName
   Get-ScheduledTask | Where-Object { $_.Principal.UserId -match $admin.SamAccountName } | Select-Object TaskName
   ```

## Do

Domain account:

```powershell
Disable-ADAccount -Identity $admin
```

Local Administrator on every member machine, with a GPO linked to the domain: Computer Configuration → Policies → Windows Settings → Security Settings → Local Policies → Security Options → **Accounts: Administrator account status** = Disabled.

One machine by hand: `Disable-LocalUser -SID (Get-LocalUser | Where-Object SID -like '*-500').SID`

## Verify

```powershell
Get-ADUser -Identity $admin | Select-Object SamAccountName, Enabled    # Enabled : False
```

Log out and back in as `breakglass` to make sure you still have Domain Admin.

## Roll back

```powershell
Enable-ADAccount -Identity $admin
```

The disabled account can still be used in Directory Services Restore Mode, so it is not lost for recovery.
