Back up, change the admin password, switch SSH to keys, and block bad IPs and domains on pfSense. GUI paths are for pfSense CE 2.7 / Plus 23+.

## 1. Back up

- GUI: **Diagnostics → Backup & Restore** → Download configuration as XML. Tick "Encrypt this configuration file" if it will be stored anywhere shared.
- Shell (SSH or console option 8), then copy it off with `scp`:
  ```sh
  cp /cf/conf/config.xml /root/config-$(date +%Y%m%d-%H%M).xml
  ls /cf/conf/backup/          # pfSense keeps its own history here too
  ```
  ```bash
  scp admin@<pfsense>:/cf/conf/config.xml ./pfsense-$(date +%Y%m%d).xml
  ```

## 2. Change the admin password

GUI: **System → User Manager** → edit `admin` → Password → Save. This changes the GUI and SSH password together.

Also check the user list for accounts you did not create, and remove them. Store the new password in your password manager **before** you log out.

## 3. SSH: keys only

1. **System → User Manager** → edit `admin` (or your own user) → **Authorized SSH Keys** → paste your public key → Save.
2. From another terminal, check `ssh -i ~/.ssh/breakglass admin@<pfsense>` works.
3. **System → Advanced → Admin Access → Secure Shell**:
   - Enable Secure Shell: ticked
   - SSHd Key Only: **Public Key Only**
   - Allow Agent Forwarding: unticked
   - SSH port: 22 (or another)
4. Save, then test again from a new terminal.
5. Under **Firewall → Rules**, allow SSH and the GUI (443) only from your admin subnet.

> [!note] No per-user exception on pfSense
> "Public Key Only" applies to every user. If `gt` must log in to pfSense with a password, leave SSH on "Password or Public Key" and protect it with firewall rules instead.

## 4. Block IPs and domains

1. **Firewall → Aliases → IP → Add**:
   - Name: `blocked_hosts`, Type: **Host(s)**
   - Add each bad IP, network or domain name. pfSense looks up domain names and refreshes them on a timer (**System → Advanced → Firewall & NAT → Aliases Hostnames Resolve Interval**).
   - For a long list, use **Import** or the **URL Table** type pointing at a text file.
2. **Firewall → Rules → Floating → Add** (applies to all interfaces):
   - Action: **Block**, Quick: ticked, Interface: all LAN-side interfaces and WAN, Direction: any
   - Destination: Single host or alias → `blocked_hosts`
   - Log: ticked
   - Add a second rule the same with **Source** = `blocked_hosts`.
3. Apply changes.
4. For a domain and all its subdomains, block it in DNS too, if clients use pfSense for DNS: **Services → DNS Resolver → General Settings → Custom options**:
   ```
   server:
   local-zone: "bad.example.com" always_nxdomain
   ```
   Save and Apply. One `local-zone` line per domain. If the pfBlockerNG package is installed, its DNSBL does the same for long lists.

Shell alternative to see the alias contents: `pfctl -t blocked_hosts -T show`.

## Verify

```sh
pfctl -t blocked_hosts -T show      # IPs in the alias
pfctl -sr | grep blocked_hosts      # the rules are loaded
```

From a LAN host: `ping <blocked-ip>` fails, and **Status → System Logs → Firewall** shows the blocks.

## Roll back

**Diagnostics → Backup & Restore → Restore** the XML from step 1, or **Diagnostics → Backup & Restore → Config History** → revert to the version before your change.
