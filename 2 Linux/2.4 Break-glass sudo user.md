Creates a local `breakglass` admin on a Linux host: key login, full sudo, and a strong password kept offline for console use. Being local, it still works if the domain or SSSD is down.

## Check

```bash
getent passwd breakglass      # exists already? local (in /etc/passwd) or from the domain?
grep breakglass /etc/passwd
. /etc/os-release; echo $ID   # ubuntu/debian use group sudo, rhel/rocky/alma use wheel
```

If `getent` finds a **domain** user called `breakglass` but `/etc/passwd` does not, creating a local one will shadow it (local `files` come first in `/etc/nsswitch.conf`). That is normally what you want; tell the domain team.

## Do

```bash
useradd -m -s /bin/bash breakglass
passwd breakglass                                   # long random password; store it offline

# Admin rights: a sudoers file is clearer than group membership
echo 'breakglass ALL=(ALL:ALL) ALL' > /etc/sudoers.d/10-breakglass
chmod 440 /etc/sudoers.d/10-breakglass
visudo -cf /etc/sudoers.d/10-breakglass

# Key login
install -d -m 700 -o breakglass -g breakglass /home/breakglass/.ssh
echo 'ssh-ed25519 AAAA...your-public-key... breakglass' > /home/breakglass/.ssh/authorized_keys
chown breakglass:breakglass /home/breakglass/.ssh/authorized_keys
chmod 600 /home/breakglass/.ssh/authorized_keys
```

Group membership works instead of the sudoers file: `usermod -aG sudo breakglass` (Debian/Ubuntu) or `usermod -aG wheel breakglass` (RHEL family).

On hosts joined to AD with SSSD, refresh the cache so the new local user is seen straight away. Use `sss_cache`; deleting `/var/lib/sss/db` also throws away cached domain logins, which then fail if the DC is unreachable.

```bash
sss_cache -E 2>/dev/null; systemctl restart sssd 2>/dev/null
```

## Verify

From another machine:

```bash
ssh -i ~/.ssh/breakglass breakglass@<host> 'sudo -l; sudo id'
```

`sudo id` must show `uid=0(root)`.

## Roll back

```bash
rm /etc/sudoers.d/10-breakglass
userdel -r breakglass
```
