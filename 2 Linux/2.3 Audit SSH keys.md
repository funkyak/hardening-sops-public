Lists every SSH key that can log in to a host, compares it with your known-good list, and removes the rest. An unknown key in `authorized_keys` is one of the most common ways back in.

## Check

1. Make a known-good list, one public key per line, on your admin machine: `known_good_keys.txt`. It holds your team's keys, including `breakglass`.
2. On the host, as root, list every key with its fingerprint:
   ```bash
   getent passwd | while IFS=: read -r user _ _ _ _ home _; do
     for f in "$home/.ssh/authorized_keys" "$home/.ssh/authorized_keys2"; do
       [[ -f $f ]] || continue
       while read -r line; do
         [[ -z $line || $line == \#* ]] && continue
         fp=$(ssh-keygen -lf <(echo "$line") 2>/dev/null | awk '{print $2}')
         echo "$user  $f  $fp  ${line: -40}"
       done < "$f"
     done
   done
   ```
3. Check whether sshd reads keys from anywhere else:
   ```bash
   sshd -T | grep -Ei 'authorizedkeysfile|authorizedkeyscommand|trustedusercakeys'
   ```
   Anything other than `.ssh/authorized_keys .ssh/authorized_keys2` (or an `AuthorizedKeysCommand` you did not set up) is suspicious in itself.

## Do

Copy `known_good_keys.txt` to the host (`/root/known_good_keys.txt`), then run as root. It moves each `authorized_keys` aside as a backup and writes back only the known-good lines.

```bash
GOOD=/root/known_good_keys.txt
getent passwd | while IFS=: read -r user _ _ _ _ home _; do
  for f in "$home/.ssh/authorized_keys" "$home/.ssh/authorized_keys2"; do
    [[ -f $f ]] || continue
    cp -p "$f" "$f.bak.$(date +%s)"
    removed=$(grep -vxF -f "$GOOD" "$f" | grep -v '^\s*$' | grep -v '^#' | wc -l)
    grep -xF -f "$GOOD" "$f" > "$f.new"
    cat "$f.new" > "$f" && rm "$f.new"
    [[ $removed -gt 0 ]] && echo "$user: removed $removed key(s) from $f"
  done
done
```

Keys must match the known-good line exactly, including the comment at the end. Normalise first if comments differ, or compare fingerprints instead.

Keep the `.bak` files as evidence until you have looked at what was removed. Then reset the password of every user who had an unknown key.

## Verify

Run Check step 2 again: only known-good fingerprints are listed. Log in with your key from a new terminal.

## Roll back

```bash
cp -p ~user/.ssh/authorized_keys.bak.<time> ~user/.ssh/authorized_keys
```

Across many hosts, Velociraptor's `Linux.Ssh.AuthorizedKeys` artifact lists every key at once ([[4.1 Hunt for persistence|4.1]]).
