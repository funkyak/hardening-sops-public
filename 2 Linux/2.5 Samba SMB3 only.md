Unlike Windows, Samba can refuse SMB1 **and** SMB2 and serve only SMB3. Windows side: [[1.1 Disable SMB1 and enforce SMB3|1.1]].

## Check

```bash
smbd --version
testparm -s 2>/dev/null | grep -Ei 'min protocol|max protocol|smb encrypt|server signing'
nmap -p445 --script smb-protocols localhost
```

## Do

1. Back up: `cp -p /etc/samba/smb.conf /etc/samba/smb.conf.bak`
2. In the `[global]` section of `/etc/samba/smb.conf`, add or change:
   ```ini
   server min protocol = SMB3
   client min protocol = SMB3
   server signing = mandatory
   # Samba 4.15+; older versions use: smb encrypt = required
   server smb encrypt = required
   restrict anonymous = 2
   map to guest = never
   ```
   Remove `guest ok = yes` and `public = yes` from every share that should need a login.
3. Check the file and restart:
   ```bash
   testparm -s >/dev/null && echo OK
   systemctl restart smbd       # Debian/Ubuntu
   systemctl restart smb        # RHEL family
   ```

## Verify

```bash
nmap -p445 --script smb-protocols <host>                                         # only 3.x dialects
smbclient -L //<host> -U <user> --option='client max protocol=SMB2'              # must fail
smbclient -L //<host> -U <user>                                                  # must work
smbclient -L //<host> -N                                                         # anonymous: must fail
```

Very old clients (Windows 7 / Server 2008 R2 without updates, some printers and scanners) cannot connect after this.

## Roll back

```bash
cp -p /etc/samba/smb.conf.bak /etc/samba/smb.conf && systemctl restart smbd
```
